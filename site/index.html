A single Go binary for macOS · no Docker · nothing to configure

Local WordPress,
for humans and agents.

agent-local creates, serves and manages WordPress sites natively — per-site PHP versions, an embedded MariaDB, real domains without port suffixes. A site goes from nothing to serving in about fifteen seconds, and a coding agent can drive every part of it that you can.

$ brew install jefrontv/tap/agent-local

Free and open source · Apple Silicon & Intel, one universal binary

The part nobody else built

    
Your agent can do everything you can.

    
Existing local-dev apps assume a human is clicking. agent-local exposes the
      same engine three ways — a dashboard for you, a CLI for scripts, and an MCP server plus HTTP API
      for Claude, Codex, or anything that speaks JSON-RPC. Not a wrapper around the GUI: the engine itself.


    

      

        

          
59 tools, no shell required

          
Create, import, snapshot, share, query the database, read the mail a form just sent —
             every capability is a typed tool call.

        

          
Errors carry the fixing call

          
A failed call names what to run next, in both CLI and MCP form — an agent with no hands
             always has somewhere to go.

        

          
No prompts, ever

          
After one-time setup, nothing asks for a password. Agents and daemons cannot answer a dialog,
             so there are none.

        

          
Closed-loop testing

             recipient, subject, decoded body. No human inbox involved.

Built for agency WordPress work

    
The things you actually do, made one command each.


    

      
Outgoing mail, captured

        
Every email a site sends lands in a per-site inbox instead of vanishing — password resets,
           form notifications, receipts. Browse it at /.agent-local/mail, or let an agent read it.

      
Database snapshots

        
Save-points taken automatically before anything destructive — import, reset, restore, delete.
           A snapshot is a plain .sql.gz, and the one taken before a delete survives it.

      
Share a work-in-progress

        
One command, one public URL — a Cloudflare quick tunnel, no account. WordPress is mapped onto
           the tunnel host automatically, and the link is verified serving before you get it.

      
Branch previews

        
Any git branch on its own domain, next to the running site — same database, copy-on-write files
           (a 555 MB preview costs ~60 MB and ~10 s). The difference between them is code.

      
Per-site PHP, 7.4 → 8.5

        
Each site runs its own php-fpm pool, so versions never conflict. Switching installs — or repairs —
           the runtime it needs, including releases Homebrew has dropped.

      
Imports that stream

        
A 7 GB LocalWP site imports in place with zero copy time. Dumps stream through a collation fixer
           with flat memory, and every stored domain is rewritten — serialized data included.

      
Missing uploads, solved

        
A local database references thousands of images the disk doesn't have. The .htaccess rule
           already in your repo is honoured automatically: local files win, the rest 302 to production.

      
WP_DEBUG without the ritual

        
wpdebug on rewrites the constants and points the log somewhere tailable. White screen →
           reproduce → read the log. Errors never render into pages.

      
Plays well on port 80

        
Binds specific addresses instead of the wildcard, so LocalWP or MAMP can run beside it.
           yield hands the ports over for a moment and takes them back.

      
A doctor that fixes

        
Every check reports with the exact command that repairs it, and doctor --fix applies
           the lot — broken PHP kegs, stale hosts entries, untrusted certs.

Under the hood

      
Boring architecture,
deliberately.

      
One shared front routes by Host header to a per-site php-fpm pool over a unix
        socket. One embedded MariaDB backs every site. State is a single JSON file written atomically, so the
        CLI, the dashboard, the daemon and several agents can act at once without clobbering each other.
        Processes are supervised, reaped, and de-duplicated — repeated restarts can't leave orphans.

      
Root is needed for exactly two things — hosts entries and trusting a TLS cert —
        and a one-time scoped allowlist removes even that prompt.
